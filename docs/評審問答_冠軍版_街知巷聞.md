# 街知巷聞 · 5 分鐘評審問答速查

回答原則：先直接回答，再給證據，最後說限制；每題 20–35 秒。

## 1. 這和 ChatGPT / 一般行程規劃有甚麼不同？

一般產品按熱門度生成文字；街知巷聞把規劃做成受限制任務，逐站調用天氣、開放、人流、導流、路線與預算工具，條件未通過不能提交。它還有「推薦 → 到店碼 → 核銷 → 歸因」閉環，能量度舊區導流，而不只輸出一篇攻略。

## 2. 哪部分真的由 Qwen 做？

單日自訂問題由 qwen3.7-plus 透過 function calling 決定下一個工具與候選行程；事實由 MCP 工具返回，最後由確定性核對器把關。多日與 90 秒評審模式採可重現工具鏈，介面會明確顯示實際引擎，不把它冒充 Qwen。

## 3. 你真的用了 QwenPaw 嗎，還是只用了 Qwen API？

兩者都有。QwenPaw 2.0.0 已部署專用 EveryLane Skill，stdio MCP 已以真實 ClientSession 完成 8 個工具的 list/call 協議測試，也保留脫敏 Session 與官方 Agent 備份。公網 FastAPI 是同一套 Agent 能力的產品化展示層。

## 4. 儀表板的數據是真的嗎？

累計試點 KPI 是賽規允許的確定性示範數據，不是真實田野研究；頁首、證據欄與 API 均明確標註。真實可操作的是 Qwen / 工具鏈、Open-Meteo、到店碼核銷、B 端 API、70 POI、無障礙資料和測試。`/api/impact/evidence` 可下載公式、種子與來源。

## 5. 既然數據是示範，為甚麼有價值？

複賽要求正是把計劃書指標做成可呈現產品。我的重點不是證明已做大規模實證，而是先把指標口徑、採集點、核銷流程和儀表板建好，使下一步真實試點不用重做系統。正式商業結論必須等真實小樣本 A/B 測試。

## 6. 到店碼如何證明真的到店？

原型中由商戶側核銷代表到店，代碼一次失效，重複核銷會被拒。正式版還會加入商戶帳戶、裝置/店員權限、核銷時間與審計日誌；目前不聲稱已具備支付級防舞弊能力。

## 7. 為甚麼不用 GPS 追蹤遊客？

因為不需要為了歸因收集持續位置。一次性到店碼能以更低私隱成本證明到店；系統免登入、不收集身份資料，區域熱度只使用彙總粒度。

## 8. 路線真的可走嗎？

目前使用真實坐標、同區約束和巷道係數估算，並以開放時間、步行距離與行程結束時間核對；不是逐路口導航。正式版會接入道路網與無障礙路徑 API，所以介面稱「站點順序示意」，不冒充導航。

## 9. 人流預測的數據來源是甚麼？

目前是星期、時段和 POI 基線的校正模型，屬估算而非官方即時人流。它適合演示導流決策，但正式部署要接入匿名感測器、官方開放資料或合作商戶觀測，再做持續校正。

## 10. Qwen 很慢或 Token 用完怎麼辦？

系統有 45 秒單次逾時、110 秒整體時間預算、零隱式長重試；受限時由同一知識庫與 7 項工具接管，軌跡和結果會標明 fallback。現場另有透明的 90 秒評審模式與 GitHub Pages 備援。

## 11. 你如何防止模型幻覺？

模型只能使用 70 個知識庫 ID；開放、人流、路線和預算都由工具計算。提交前會再檢查 ID、去重、同區、當日開放、少步行和預算；不合格就移除、重建或由工具鏈接管。

## 12. 商業模式的第一個付費客戶是誰？

最容易起步的是舊區商戶聯盟或酒店禮賓部。商戶可先用低風險到店碼按效果試點；酒店可用 API 快速提供多語深度遊。當有真實核銷與區域數據後，再向文旅部門提供彙總儀表板。

## 13. 如何避免付費商戶影響推薦公平？

先滿足日期、開放、距離、興趣、無障礙和人流條件，再在同等候選中考慮合作商戶；付費不應覆蓋安全與相關性。介面需標示推廣，並保留非商業舊區點，避免把導流變成廣告榜。

## 14. 競爭者複製景點資料怎麼辦？

景點清單不是護城河。真正難複製的是三者結合：以承載平衡為目標的決策規則、失敗恢復與核對工具鏈，以及由到店碼累積的「推薦—到訪—轉化」反饋閉環。

## 15. 怎樣擴展到大量用戶？

讀取型 POI 與成效 API 可水平擴展；模型調用以限流、快取和佇列控制；到店碼從 JSON 原型遷移到有唯一索引與交易的資料庫；天氣與知識庫使用快取。現階段先以小規模商戶試點驗證，不會過早做重型架構。

## 16. 無障礙資訊如何保證正確？

目前是公開資料、已知地點人工覆寫和類別規則的初版，70/70 有標註，但不宣稱等同官方無障礙審核。介面提供具體提示並提醒現場確認；下一步與長者/輪椅使用者實地共測。

## 17. 一人團隊是否風險太高？

風險存在，所以用可重現腳本、Git 版本、最小化部署、靜態備援與 641/119/101/8 套件測試降低單點風險。架構模組化，商戶、資料與模型層可以在組隊後分工擴展。

## 18. 下一個最重要里程碑是甚麼？

不是再加功能，而是取得 3–5 間商戶同意，做小樣本真實 A/B 試點：對照一般熱門推薦與舊區導流，在不增加熱門點負荷下量度到店核銷、完成率和商戶反饋。

## 19. 為甚麼這個項目應該第一名？

它不是只有創意或只有工程：以舊區導流形成差異化，用 QwenPaw + MCP 完成真正多步任務，再以到店碼和 B 端 API 把社會價值做成可歸因商業閉環。更重要的是，計劃書的晉級後承諾已全部變成可操作、可核驗、且限制透明的產品。
